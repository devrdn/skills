# Стиль русского текста

Голос главы - опытный преподаватель и инженер, который объясняет первокурснику вслух: просто, точно, спокойно. Это не документация API, не научная статья и не блог.

## Образец

Так звучит текст автора (глава 6 курса Cloud Computing, раздел "Где хранить файлы приложения"). Ориентируйся на него по длине предложений и по тому, как раздел ведёт студента: проблема на конкретном сценарии, шаги по порядку, определение, объяснение рисунка.

```markdown
Последнее ограничение проявляется, как только серверов становится два. Допустим, приложение работает на двух экземплярах:

1. Пользователь загружает фотографию. Запрос попадает на первый сервер, и файл сохраняется на его диск.
2. Через минуту пользователь открывает страницу с фотографией. Запрос попадает на второй сервер.
3. На диске второго сервера фотографии нет, и пользователь видит ошибку.

Синхронизировать каталоги между серверами можно, но это быстро превращается в самодельную распределённую файловую систему. Облачные архитектуры решают задачу проще: файлы выносят с серверов в общее хранилище.

**Сервер без состояния (stateless server)** - сервер, который не хранит на своих дисках пользовательские данные. Его можно удалить и заменить новым без потери данных.

![Файлы на дисках экземпляров и файлы в общем хранилище](../_images/06/stateless_servers.svg)

_6.1. Файлы на дисках экземпляров и файлы в общем хранилище_

На рисунке 6.1 слева каждый экземпляр хранит файлы на своём томе, и второй сервер не видит, что загрузили на первый. Справа оба экземпляра пишут в одно хранилище, и любой сервер можно заменить.
```

## Как писать предложение и абзац

- Одно предложение - одна мысль, обычно 8-20 слов. Несколько очень коротких фраз подряд об одном и том же объедини в одно предложение. Предложение длиннее 25 слов раздели на два.
- Все слова на месте. Если сказуемое опущено, ставь тире: "для второго сервера - другой".
- Связки "поэтому", "то есть", "таким образом", "следовательно" - не больше одной на абзац. Вместо "то есть" ставь двоеточие или тире. Если вывод и так следует из предыдущего предложения, связка не нужна.
- Два действия с разными участниками - два предложения, а не одно, склеенное запятыми.
- Действие совершает тот, кто его на самом деле делает: считает функция, а не вызов; собирает программу компилятор, а запускает её пользователь.
- Глаголы простые и точные: "это" или тире вместо "является" и "представляет собой", "делает" вместо "осуществляет", "может" вместо "имеет возможность", "чтобы" вместо "для того чтобы".
- Русский термин целиком на русском, английское название - в скобках при первом упоминании.
- Абзац из 2-5 предложений об одной мысли. Сначала мысль, потом термин и детали.
- Разобранный пример начинается словами "Рассмотрим пример.". Переход называет, что мы делаем и на чём: "Теперь применим отладчик к примеру "Бой до победы".".
- Бытовая аналогия нужна, только если она строит правильную модель; после неё текст возвращается к технической модели.
- Абзац заканчивается последним полезным фактом.
- Персонажи вступительной истории не появляются в основном тексте. В технических частях не придумывай людей с именами.

## Плохо и хорошо

| Плохо | Хорошо | Что исправлено |
| --- | --- | --- |
| Для первого сервера нужен один диск, для второго другой. | Для первого сервера нужен один диск, для второго - другой. | Тире на месте пропущенного слова |
| Итог: четыре удара. | Игрок нанёс четыре удара. | Обрывок стал предложением |
| Сервер получил запрос. Он проверил токен. Токен устарел. Сервер вернул ошибку. | Сервер получил запрос и проверил токен. Токен устарел, и сервер вернул ошибку `401`. | Короткие фразы объединены в два предложения |
| Поэтому при сбое записи не теряются, то есть потеря данных равна нулю. | При сбое подтверждённые записи не теряются: потеря данных равна нулю. | Лишние связки убраны, вместо "то есть" двоеточие |
| Сначала вычисляется `a + 5`, то есть `35`, это значение попадает в `x`, и функция вернёт `23`. | Сначала вычисляется `a + 5`, получается `35`. Это значение попадает в `x`, и функция возвращает `23`. | Длинная склейка разделена на два предложения |
| Цикл делает пять шагов и называет переменную внутри тела. | Тело цикла выполняется пять раз, и на каждом проходе переменная `i` получает новое значение. | Точные глаголы вместо "делает" и "называет" |
| Этот способ называется кэшированием. **Кэширование (caching)** - ... | **Кэширование (caching)** - ... | Термин не объявляется дважды подряд |
| Развёртывание Multi-AZ DB instance повышает доступность. | **Развёртывание Multi-AZ с одним резервным экземпляром (Multi-AZ DB instance deployment)** повышает доступность. | Русский термин на русском, английский в скобках |

## Признаки сгенерированного текста

Ищи скопления признаков: один признак сам по себе мало что доказывает.

| Признак | Пример | Что сделать |
| --- | --- | --- |
| Значимость без содержания | "играет ключевую роль", "в современном мире", "неотъемлемая часть" | Заменить конкретным фактом или удалить |
| Безымянные авторитеты | "специалисты считают", "исследования показывают" | Дать сноску на источник или сказать утверждение прямо |
| Пустые анонсы | "В этом разделе мы рассмотрим", "Давайте разберёмся", предложение, повторяющее заголовок | Начать с содержания |
| Канцелярит | "является", "осуществляет", "производится", "для того чтобы" | Простой глагол (см. выше) |
| "Не просто X, а Y" | "Это не просто цикл, а мощный инструмент" | Сказать, что это |
| Тройки и размахи по инерции | три прилагательных подряд, "от новичков до профессионалов" | Оставить столько, сколько есть по смыслу |
| Синонимы по кругу | "цикл", "конструкция повторения", "механизм итерации" | Один термин, определённый в главе |
| Глубокомыслие | "на самом деле", "по сути", "важно понимать, что", "стоит отметить" | Убрать рамку, оставить утверждение |
| Каскад оговорок | "может потенциально в некоторых случаях" | Одна оговорка, если факт её требует |
| Ответы на несуществующие возражения | "Это не значит, что...", "Конечно, можно было бы..." | Удалить, если студент так не думает |
| Афоризмы и драматические концовки | "И это работает.", "Вот и всё." | Удалить; один афоризм на главу допустим |
| Мотивационные финалы | "теперь вы готовы к большим проектам" | Закончить последним фактом |
| Одинаковое начало предложений | три предложения подряд начинаются с "Это..." | Перестроить по смыслу |
| Телеграфный стиль | "Исправление: возвращать счётчик", "Фильтр: какие объекты", ряд фраз по 3-5 слов | Полное предложение средней длины |
| Жирный ради вида | жирные мини-заголовки и выделения | Жирный только в определении |

## Что не считается признаком

- Определения, пометка "Рассмотрим пример.", таблицы трассировки, выводы программ, пошаговые разборы. Это жанр учебника.
- Повтор правила сразу после примера, который его показывает, и резюме в конце главы.
- Простые предложения средней длины: для этой аудитории это достоинство.
- Сухие нейтральные формулировки в технических частях.
- Одна уместная шутка или яркая метафора, которая строит верную модель.
- Фразы в кавычках, коде, сообщениях компилятора и примерах, где фраза обсуждается.
- Списки: перечисление из трёх и более пунктов оформляется списком (SKILL.md, раздел "Списки и таблицы").

## Правка языка ("хуманизируй", "звучит как ИИ", "поправь стиль")

1. Отметь признаки из таблицы в каждом разделе.
2. Перепиши отмеченные абзацы вокруг их главной мысли, а не фразу за фразой.
3. Сверь с исходником: не добавилось и не потерялось ни одного факта, числа, термина, примера или сноски.
4. Не выдумывай факт, пример или источник, чтобы текст звучал живее.
