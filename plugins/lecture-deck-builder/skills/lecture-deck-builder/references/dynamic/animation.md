# Динамический режим: анимация, стрелки и механики

Единственный источник правил анимации: на этот файл ссылаются рецензент плана и проверка анимаций. Читай до плана по слайдам и при сборке каждой схемы.

## Анимация, стрелки и механики

Анимация - главное, чем динамическая презентация лучше PPTX, и её не ограничивают ни по количеству, ни по видам. Каждый процесс главы движется: запрос идёт по стрелке, строка попадает в буфер, значения встают на места меток, страница собирается из частей, упавший сервер заменяется новым. Шагов у схемы столько, сколько этапов у процесса.

**Новая механика.** Если процессу нужно движение, которого нет в заготовке, сделай для него новую механику: свой класс в `src/topic.css` и шаги через `data-in`, `data-out`, `data-on`, `data-cur`. Не нужно втискивать процесс в точку на стрелке, если он лучше виден как заполнение буфера или переезд значения. Новая механика называется в плане («new mechanic: ...») и в отчёте. Удачную механику автор может попросить перенести в `mechanics.css` заготовки.

**Что делает анимацию шумом.** Автор жаловался не на количество анимации, а на движение без смысла и плохую сборку: точки на стрелках, по которым ничего не идёт; элементы, которые появляются раньше своего шага; стрелки мимо узлов; анимация функции до того, как сказано, что она делает. Поэтому у каждой анимации должен быть смысл и правильная сборка.

**Смысл.**

1. Движение показывает то, чего не видно на статичной картинке: передачу между частями (данные, HTML, запрос, вывод), порядок выполнения, превращение «было → стало», замену, отказ. Вопрос для проверки: «что студент увидит в движении такого, чего не покажет статичный слайд?». Если ответа нет, слайд статичный: определение, карточки фактов, плюсы и минусы, справочная таблица, синтаксис, итоги.
2. Перед анимацией функции стоит её карточка (`references/dynamic/content.md`).
3. Один шаг - одно изменение, и это то изменение, которое названо в подписи шага. Если на шаге меняются три вещи, это три шага. Длинный процесс можно разбить на два слайда, если схема перестаёт помещаться.
4. Ничего не появляется раньше своего шага: узел, его стрелка и подпись выходят на одном шаге. Подписей `.caps` столько же, сколько шагов, плюс шаг 0.

**Точки на стрелках.**

| Стрелка | Когда |
|---|---|
| `.link` | связь, по которой ничего не движется: статичная |
| `.link.on` (через `data-on="k"`) | шаг дошёл до этой связи: стрелка становится тёмной |
| `.link.flow` + `data-cur="k"` | по стрелке на шаге k что-то передаётся: бежит точка |
| `.link.r` | цвет «работает» вместо цвета «сборка» |
| `.link.x` | передача с ошибкой: красная стрелка и точка |
| `.link.v` | вертикальная стрелка |

- Точка бежит только на тех шагах, когда по стрелке что-то передаётся: `class="link flow" data-on="2" data-cur="2"`. Если передача идёт несколько шагов подряд, `data-cur="2 3 4"`. Когда передача закончилась, стрелка остаётся тёмной и неподвижной: так видно, где поток сейчас.
- Стрелки-отношения («расширяет», «подключает», «содержит», «видит», «зависит от») рисуются без точки.
- Если сомневаешься, спроси себя: что именно едет по стрелке? Если ответ - существительное (запрос, строка HTML, образ, журнал), точка нужна.
- `data-on="1 3"` включает стрелку на шагах 1 и 2, с шага 3 она снова гаснет. Так останавливают поток к упавшему серверу.
- Наконечник - ровный треугольник по центру линии. Точка - круг 10 px; она плавно разгоняется и тормозит, перед наконечником гаснет.

**Геометрия.**

- Стрелка соединяет два видимых соседних узла в одном ряду (`.dx`) или стоит вертикально посередине колонки. Стрелок в пустоту и к ещё скрытому узлу нет.
- Веер стрелок (`.fan > .fr`) заканчивается либо у каждой стрелки своим узлом, либо одним высоким узлом, растянутым на все ряды веера (`.dx.st`).
- Наконечник выступает на 10 px за конец линии; правый отступ `.link` в 14 px не даёт ему зайти на рамку узла. Не уменьшай этот отступ.
- Узлы не сжимаются до ширины меньше своего текста (`flex-shrink:0` в `mechanics.css`): сжимаются только стрелки. Узлу с переносимыми фишками (`.chip`) задаётся ширина, иначе фишки вылезают за рамку. Длинную строку без пробелов (путь файла, сообщение) разбивают на две строки вручную.
- Код не сжимается по высоте во flex-колонке (`pre.code{flex-shrink:0}`): иначе последние строки обрезаются.
- У каждого узла рамка и иконка (`references/dynamic/icons.md`).

**Цвета состояний.**

| Состояние | Класс | Цвет |
|---|---|---|
| текущий участник шага | `.hot.on`, `data-cur` → `.cur` | индиго |
| готовый результат, безопасный вывод | `.on` | зелёный |
| ошибка, опасность | `.bad.on`, `.link.x` | красный |
| вышел из строя | `.down.on` | бледный серый |
| не участвует на этом шаге | `.dim` + `data-cur` | серый |

Узел-источник (браузер, данные, шаблон) никогда не зелёный: зелёный - это результат.

**Код по шагам.** Построчная подсветка `<xcode cur="1:2-3;2:5">` нужна, когда смысл именно в порядке выполнения (три фазы функции). В остальных случаях код подсвечивается постоянно (`⟪...⟫`) или не подсвечивается.

**Механики заготовки** (`deck.css`, `mechanics.css`):

| Механика | Разметка | Для чего |
|---|---|---|
| точка по стрелке | `.link.flow` + `data-on`, `data-cur` | передача между узлами |
| появление по шагам | `data-in`, `data-out` | новый участник процесса |
| подсветка текущего | `data-cur="k"` или `"k m"` | кто работает на этом шаге |
| смена состояния | `data-on` + `.on`, `.bad`, `.down`, `.hot` | результат, ошибка, отказ |
| переезд | `.mover` + `--dx` | тег или значение переходит на новое место |
| каскад слоёв | `.cascade .layer` | пересборка слоёв после изменённого |
| мини-страница из частей | `.page > .bar + .body > .part` (`.lg`, `.vw`) | страница собирается из частей, логика и представление |
| место вставки | `.slot` | пустое место, которое заполняется значением |
| фишки значений | `.chips > .chip` | данные, которые передаются или подставляются |
| узел-файл | `.fnode > .fh + .m` или `.code` | файл или функция с содержимым |
| стопка буферов | `.bufs > .buf` | вложенные буферы, стек вызовов |
| код по шагам | `<xcode cur="..." on="..." in="...">` | порядок выполнения строк |
| длинный список | `data-gen="series"` | двенадцать факторов, семь уровней |

Механики сочетаются: строка кода подсвечивается (`xcode cur`), по стрелке бежит точка (`data-cur`), фишка появляется в буфере (`data-in`) - всё на одном шаге, если это одно событие.
