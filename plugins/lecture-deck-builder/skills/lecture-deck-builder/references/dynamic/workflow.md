# Динамический режим: результат, порядок работы и проверки

Динамический режим: лекция в виде интерактивной HTML-презентации вместо PPTX. Студентам такую интереснее смотреть и проходить. Делается по запросу: «интерактивная», «динамическая», «HTML-презентация», «для Moodle», «SCORM».

Содержание подчиняется тем же правилам, что и обычная лекция (`references/common/content-rules.md`). Источник, план по слайдам и проверка плана агентом описаны в SKILL.md (шаги 1-3) и выполняются до всего, что описано здесь. Эти файлы описывают только то, что отличает динамический режим. До плана по слайдам прочитай целиком этот файл, `references/dynamic/content.md` и `references/dynamic/animation.md`: план динамической лекции уже называет, что движется на каждом слайде.

Остальные правила режима разложены по файлам и читаются, когда нужны:

| Файл | Что в нём | Когда читать |
|---|---|---|
| `references/dynamic/content.md` | версия для пары и студенческая, карточки функций, «Реализация метода», определения, выноски, рисунки как живые схемы, стенды, вопросы, командный квиз | до плана по слайдам |
| `references/dynamic/animation.md` | анимация, стрелки, геометрия схем, цвета состояний, механики заготовки, новые механики | до плана и при сборке каждой схемы |
| `references/dynamic/icons.md` | иконки AWS и контурные иконки узлов | при сборке схем |
| `references/dynamic/markup.md` | справочник разметки: шаги, классы, `<xcode>`, значки | при написании `slides.html` |
| `references/dynamic/design.md` | бренд, титульный слайд, шрифты, запреты шаблонного дизайна | при написании слайдов и стилей |
| `references/dynamic/performance.md` | слабые компьютеры, лёгкий режим, размер файла, совместимость с Chrome 109 | при новой механике или правке стилей и движка |
| `references/dynamic/moodle.md` | навигация, клавиши, SCORM 1.2, загрузка в Moodle | при вопросах о навигации, SCORM и Moodle |

## 1. Что получается на выходе

`python3 build.py` собирает из одного источника `src/slides.html`:

| Файл | Для чего |
|---|---|
| `dist/<Курс>_<NN>_<Тема>_пара.html` | показ на лекции, открывается двойным щелчком и работает без интернета |
| `dist/<Курс>_<NN>_<Тема>_пара_квиз.html` | то же и командный квиз в конце; только HTML, без SCORM |
| `dist/<Курс>_<NN>_<Тема>_студенты.html` | самостоятельное изучение |
| `dist/moodle/<Course>_<NN>_<Topic>_pair_SCORM.zip` | пакет SCORM 1.2 для Moodle, версия для пары |
| `dist/moodle/<Course>_<NN>_<Topic>_students_SCORM.zip` | пакет SCORM 1.2 для Moodle с оценкой за итоговый тест |

Шрифты, иконки и фоны встроены в файл, внешних запросов нет. Вопросы командного квиза попадают только в файл `_пара_квиз`: из остальных версий сборщик вырезает их и из слайдов, и из данных, чтобы студенты не нашли ответы в коде страницы. Второй дизайн (`tokens-mine.css`) собирается только по просьбе автора: `python3 build.py --variant`. Фрагменты для публикации артефактом: `--artifact`.

Сдаются пять файлов из таблицы. Если автор просит и динамическую, и обычную презентацию, к ним добавляются четыре файла обычного режима (PPTX и PDF). Имена SCORM-пакетов пишутся латиницей: Moodle и Windows иногда портят кириллицу в именах архивов.

## 2. Порядок работы

К началу этого раздела уже готовы глава, прошлая глава и `plan.md`, проверенный агентом (SKILL.md, шаги 1-3). Слайды пишутся по плану: строка плана становится слайдом, строка «motion» - шагами схемы.

1. Скопируй заготовку: `cp -R <skill>/assets/interactive <папка темы>/presentation`. Положи туда `plan.md`.
2. Заполни `CONFIG` в начале `build.py`: код темы, префиксы имён, заголовки, папку рисунков главы, контурные иконки.
3. Напиши `src/slides.html` и `src/data.js` по плану и по образцу из заготовки. В образце есть по одному слайду каждого вида; разметку бери оттуда, а не придумывай заново. Механики анимации возьми из `src/mechanics.css` (`references/dynamic/animation.md`); новую механику темы, если план её предлагает, напиши в `src/topic.css`.
4. Стенды темы, если они нужны, допиши в `src/stands.js` (объект `S`). Вопросы командного квиза добавь в `DATA.quiz` (`references/dynamic/content.md`).
5. Собери презентацию, открой каждую из трёх версий в браузере на 1280×720 (через локальный сервер `python3 -m http.server` в папке `dist`) и выполни в странице содержимое `scripts/check_fit.js`: вставь его в консоль или передай инструменту выполнения JavaScript. Проверка провалена, если отчёт начинается со слов «ЕСТЬ ПРОБЛЕМЫ» или называет внешние запросы. Как чинить: сократи текст, разбей слайд, уменьши схему; размер основного текста не уменьшай.
6. Запусти рецензентов из `agents/README.md`: по фактам, проверку кода (если в лекции есть код), студента-читателя, языкового редактора и проверку анимаций (`agents/animation-checker.md`). Им нужен `story.md` - текст собранной студенческой версии слайд за слайдом с вопросами и ответами: `python3 <skill>/scripts/story_html.py dist/<...>_студенты.html > story.md` (нужен node). Студент-читатель читает только `story.md`; рецензент по фактам и языковой редактор получают `story.md`, а при необходимости и исходники `src/slides.html` и `src/data.js` (оба файла читаются как текст). Версию для пары с квизом можно выгрузить так же и отдать рецензенту по фактам ради вопросов квиза. Слова-связки и длину текста `lint_content.js` здесь не ловит, их проверяет языковой редактор. Замечания проверки анимаций вноси все, кроме противоречащих главе и правилам из `references/dynamic/animation.md`; после этого запусти проверку ещё раз.
7. Просмотри на скриншотах каждую живую схему на всех шагах. В скрытой панели браузера анимация может замереть: тогда добавь стиль `.slide.active{animation:none}` в открытую страницу через JavaScript (не в исходники) и сними скриншот ещё раз.
8. Сдай пять файлов и напиши отчёт по SKILL.md: число слайдов в каждой версии, какие рисунки стали схемами, какие механики добавлены, что пропущено.

Примеры тем на машине автора, если они есть: `php/12_Templating/presentation/` в репозитории `courses/draft` (новый движок: карточки функций, механики, квиз, `<xcode>`) и `cloud-computing/12_Containers_And_Cloud_Native/presentation/` (ранний движок: у стрелок там нет класса `flow`).

## 3. Проверки перед сдачей

- `scripts/check_fit.js` в открытой странице на 1280×720 на каждой из трёх версий. Он проходит все шаги всех слайдов и сообщает:
  - что не помещается в сцену;
  - обрезанный текст и код, обрезанный по высоте;
  - текст, который выходит за рамку своего узла (по прямоугольникам самого текста, а не блока);
  - стрелку, у которой нет видимого узла с одной из сторон, и наконечник, который заходит на рамку;
  - иконку, которая не встроилась;
  - внешние запросы.
- Скриншоты каждой живой схемы на каждом шаге:
  - стрелки соединяют нужные узлы;
  - подпись шага совпадает с тем, что изменилось;
  - точка бежит только по стрелке, по которой сейчас что-то передаётся;
  - ничего не появилось раньше своего шага.
- Проверка анимаций (`agents/animation-checker.md`) не нашла ни процесса без движения, ни движения без смысла, ни функции без карточки, ни сломанной сборки.
- Лёгкий режим (клавиша L): схемы читаются, ничего не пропало.
- Квиз: в `_пара_квиз` есть вопросы, «Время вышло» и ответы; в версиях `_пара` и `_студенты` нет ни слайдов квиза, ни `quiz:` в коде страницы.
- Рецензенты:
  - по фактам;
  - студент-читатель, только по студенческой версии;
  - языковой редактор с блоком «Языковой фокус» из SKILL.md.
- SCORM на тестовом API. Перед загрузкой страницы задай `window.API` с методами `LMSInitialize`, `LMSSetValue`, `LMSGetValue`, `LMSCommit` и `LMSFinish`, которые записывают вызовы, и проверь:
  - вход;
  - возврат на последний слайд;
  - оценку 70 за 7 верных ответов из 10;
  - статус `completed`.
