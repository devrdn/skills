# Обычный режим: PPTX и PDF

Этапы сборки в обычном режиме. Источник, план по слайдам и проверка плана идут раньше и описаны в SKILL.md; переходи к этому файлу, только когда рецензент плана принял `plan.md`.

## Содержание

1. Подготовка
2. content.js
3. Этап B: факты, код, связность, язык
4. Сборка версии преподавателя
5. Этап C: проверка вёрстки
6. Этап D: последняя языковая вычитка
7. Студенческая версия и сдача файлов

Версия для пары описана отдельно: `references/regular/pair-deck.md`.

## 1. Подготовка

```bash
python3 <skill>/scripts/setup.py <workdir>      # например, /home/claude/deck; можно запускать повторно
```

В этой рабочей папке лежат content.js, plan.md, story.md, рисунки (`img/`) и результаты сборки. Рисунки, на которые ссылается глава, кладутся в `img/` с префиксом лекции (`l6_...png`). SVG переводится в PNG так: `python3 -c "import cairosvg; cairosvg.svg2png(url='a.svg', write_to='a.png', scale=2.5, background_color='white')"` (если cairosvg не установлен: `pip install cairosvg`).

## 2. content.js

Напиши `content.js` по проверенному плану, следуя `references/regular/slide-patterns.md`, `references/regular/slide-api.md` и `assets/example_content.js`. Длинную главу пиши по разделам. Прежде чем переходить к следующему разделу, прочитай каждый его слайд так, как прочитает студент, и проверь:

- слайд устроен так: заголовок, вводная строка, один основной блок, вывод;
- слайд понятен сам по себе, без слов-связок и рассказа;
- ни один блок не длиннее двух строк;
- списки стоят только там, где пункты однородны;
- новые термины вводятся только на карточках определений;
- код и рисунки читаются с последнего ряда.

Пиши коротко с самого начала: выбрать одну мысль на блок легче, чем потом сокращать готовый абзац.

```bash
node lint_content.js content.js --forbid "John,Emma"      # и имена персонажей истории из главы
node story.js content.js > story.md
```

Исправь каждый ERROR. Предупреждения WARN тоже исправляй, а не оставляй: они указывают как раз на те слайды, на которые жалуется автор. Просмотри каждый знак «⚠» в story.md: если имя используется раньше, чем его показал какой-либо слайд, значит, слайд стоит не на своём месте или пропущен шаг.

## 3. Этап B: факты, код, связность, язык

Запусти рецензента по фактам, проверку кода, студента-читателя и языкового редактора **в одном сообщении** (`agents/README.md`). В промпт языкового редактора добавь блок «Языковой фокус» из SKILL.md. Примени замечания так, как сказано в `agents/README.md`, снова запусти линтер и story.js, а если в первом круге нашлось больше чем несколько проблем, проведи второй круг студента-читателя и языкового редактора.

## 4. Сборка версии преподавателя

```bash
python3 make.py content.js <Name>        # -> <Name>.pptx, <Name>.pdf; печатает WARN, check_all, footer_scan
```

Номер в `WARN [слайд N]` совпадает с номером страницы PDF. Повторяй сборку, пока не исчезнут все `WARN`, `check_all.py` не станет сообщать ни о чём, кроме титульной страницы («стр 1: край» - это ожидаемо), а `footer_scan.py` не покажет 0 наложений. Если текст не помещается, сначала сократи его, потом раздели слайд или переведи его в `codepair`/`columns`; основной текст никогда не уменьшай: его должны прочитать и с последнего ряда.

## 5. Этап C: проверка вёрстки

```bash
mkdir -p pages && pdftoppm -r 60 -png <Name>.pdf pages/pg
```

Запусти агентов проверки вёрстки, по одному на каждые ~40 страниц, всех в одном сообщении. Пока они работают, сам просмотри страницы. Исправь, пересобери, снова запусти линтер; если исправления затронули текст, заново создай story.md и перечитай изменённые слайды.

## 6. Этап D: последняя языковая вычитка

Главная повторяющаяся жалоба автора после сдачи - русский текст формально правильный, но звучит не «складно». Этап B читает презентацию раньше, чем формулировки меняются при исправлениях сборки и вёрстки и при поздних сокращениях, поэтому после этапа C прочитай ещё раз **окончательный** текст:

```bash
node story.js content.js > story.md
```

Запусти языкового редактора (opus) один раз по новому story.md, с блоком «Языковой фокус» в промпте. Примени замечания, пересобери и просмотри изменённые страницы. Если он вернул больше ~10 существенных замечаний, примени их и запусти его второй раз.

## 7. Студенческая версия и сдача файлов

```bash
STUDENT=1 python3 make.py content.js <Name>s
python3 /mnt/skills/public/pptx/scripts/office/validate.py <Name>.pptx    # если есть скилл pptx
```

На выходе всегда **четыре файла**. Скопируй все четыре по именам в папку для сдачи (`/mnt/user-data/outputs/`, если она есть); не пользуйся `cp <Name>*`: так захватятся и побочные файлы `.noanim` и `.anim.json`. Проверь, что файлы там появились, и отправь все четыре (через SendUserFile, если он доступен):

- `<Course>_<NN>_<Тема>.pptx` и `.pdf`: версия преподавателя;
- `<Course>_<NN>_<Тема>_студенты.pptx` и `.pdf`.

`<Course>`: `Cloud`, `Веб`, `Программирование` или короткое название нового курса. Тема - 2-4 слова из названия главы, соединённые подчёркиванием (`Введение_в_AWS`, `ООП_в_PHP_часть_1`).

Правки: сохрани предыдущую версию (`cp content.js content.v1.js`), меняй только content.js, пересобери обе версии, запусти все проверки и снова отправь четыре файла.
