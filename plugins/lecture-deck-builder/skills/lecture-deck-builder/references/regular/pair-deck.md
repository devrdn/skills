# Версия для пары (обычный режим)

Читай этот файл, когда автор попросил версию для пары.

Вторая презентация, только для преподавателя: её показывает на лекции сам автор. Рассказывает автор, поэтому на слайдах структура и факты, а не связный текст. Делай её, когда автор просит короткую презентацию, презентацию «для пары» или «для препода», обычно после того, как основная готова.

## Что входит

- **Вся глава, по разделам и в её порядке**: каждый раздел главы открывается разделителем, ничего не пропущено. Короткая не значит неполная: каждое понятие, термин и сравнение главы есть на слайдах, только в сжатом виде.
- **Не больше 60 страниц** (желательно), считая разделители и обе страницы каждого вопроса. Если глава не помещается, объедини связанные слайды в один, с карточками или со сравнением, убери повторяющиеся примеры и сохрани каждое понятие. Если всё равно нужно больше 60, собери её и в отчёте скажи, сколько получилось страниц и почему.
- **Все рисунки главы, и только они**: рисунки, на которые текст главы ссылается по номеру, с номерами главы, заданными явно (`num: "7.3"`). Рисунки из репозитория, на которые глава не ссылается, не входят.
- **Вопросы по ходу лекции** из основной презентации (`predict`, вопрос и ответ на разных страницах) и один вопрос на разминку по прошлой теме. Без командного квиза, без результатов обучения, без списка для самопроверки.
- Слайд **плана** и слайд **итогов** («Резюме», в конце), оба в виде карточек.
- Название презентации - название лекции. Никогда не пиши на слайде «кратко», «краткий обзор» или «короткая версия».

Если версия для пары делается без основной презентации, она всё равно начинается с плана по слайдам и проверки плана (SKILL.md, шаги 2-3).

## Как выглядит: без простых маркированных списков

Простые маркированные пункты плохо читаются с последнего ряда и все похожи друг на друга. Выбирай макет по форме содержания:

| Содержание | Тип | Пример |
|---|---|---|
| Однородные понятия, термины, свойства, плюсы и минусы | `cards` | Свойства ACID (2×2), шесть моделей NoSQL |
| Две вещи, сравнённые по одним и тем же критериям | `versus` | ACID или BASE, Multi-AZ и реплика для чтения |
| Процесс или последовательность | `steps` | транзакция, запись в WAL, восстановление на момент времени |
| Несколько ключевых чисел | `stats` | Aurora: 6 копий, до 15 реплик |
| Данные в три столбца и больше | `table` | составной ключ таблицы |
| Рисунок главы | `image` | |
| Код, ради которого слайд и сделан | `code` | запрос через AWS CLI |
| Вопрос аудитории | `predict` | |

Как писать блоки:

- Карточка: `label` - категория в 1-3 слова («Термин», «Проблема», «Плюс»), `title` - термин или короткое утверждение, `text` - одно законченное предложение примерно из 6-14 слов. Карточка - не телеграмма: она читается как фраза.
- Однородные карточки на одном слайде пиши в одной грамматической форме.
- Цвет несёт смысл, только когда он задан намеренно (`color` для «хорошо/плохо», последний шаг - `lastAccent`); в остальных случаях движок чередует два цвета бренда.
- На слайде 2-6 карточек; 4 карточки идут сеткой 2×2. Для длинных текстов делай меньше столбцов (`cols`).
- Бери материал из основной презентации: вопросы, таблицы, код и слайды с рисунками из content.js через вспомогательную функцию `pick`, чтобы тексты совпадали с одобренной основной презентацией.

## Типы слайдов для версии для пары

Все эти типы принимают `title` и необязательные `intro`, `after`, `setPart`, как и основные.

```js
{ type: "cards", title, cols?, mono?, cards: [{ label?, title?, text?, color? }] }
{ type: "steps", title, lastAccent?, steps: [{ title, text?, color? }] }          // 3-5 шагов
{ type: "stats", title, cols?, stats: [{ value, label?, text?, color? }] }       // 2-4 плитки
{ type: "versus", title, left, right, labelW?, rows: [[criterion, leftText, rightText]] }
```

## Сборка и проверки

Работай в рабочей папке основной презентации, после того как основная собрана. `setup.py` уже скопировал туда `pair_layouts.js` и `deck_text.js`.

1. Создай движок и сценарий сборки для версии для пары. Основной движок остаётся нетронутым:
   ```bash
   python3 - <<'EOF'
   src = open("build_modern.js").read()
   lay = open("pair_layouts.js").read()
   assert src.count("const RENDER = {") == 1
   src = src.replace("const RENDER = {", lay + "\nconst RENDER = {\n  cards: cardsSlide, steps: stepsSlide, stats: statsSlide, versus: versusSlide,", 1)
   open("build_pair.js", "w").write(src)
   EOF
   sed 's/"build_modern.js"/"build_pair.js"/' make.py > make_pair.py
   ```
2. Напиши `content_pair.js`: он начинается с `delete process.env.STUDENT; const full = require("./content.js");` и вспомогательной функции `pick(type, title, over)`.
3. Собери: `python3 make_pair.py content_pair.js <Name>_пара`. Исправь каждый WARN (слово не помещается в карточку, текст выходит за край): сократи или раздели слайд; добивайся 0 WARN и 0 наложений на нижний колонтитул. `lint_content.js` и `story.js` новые типы не поддерживают.
4. Языковая вычитка: `node deck_text.js content_pair.js > deck_text.md`, затем запусти языкового редактора по deck_text.md (номера там - индексы слайдов, а не страницы) с блоком «Языковой фокус». Примени замечания, пересобери.
5. Проверка вёрстки: отрисуй страницы (`pdftoppm -r 60`) и просмотри все сам или, если презентация длинная, запусти агентов проверки вёрстки.
6. Проверь PPTX валидатором и сдай **два файла**: `<Course>_<NN>_<Тема>_пара.pptx` и `.pdf`. В отчёте назови число страниц, использованные макеты и всё, что не поместилось.
