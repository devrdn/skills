# Интерактивная презентация (HTML и SCORM)

Режим для лекции в виде интерактивной HTML-презентации вместо PPTX. Студентам такую интереснее смотреть и проходить. Делается по запросу: «интерактивная», «динамическая», «HTML-презентация», «для Moodle», «SCORM».

Содержание подчиняется тем же правилам, что и обычная лекция (`content-rules.md`). Этот файл описывает только то, что отличает интерактивный режим.

## 1. Что получается на выходе

`python3 build.py` собирает из одного источника `src/slides.html`:

| Файл | Для чего |
|---|---|
| `dist/<Курс>_<NN>_<Тема>_пара.html` | показ на лекции, открывается двойным щелчком и работает без интернета |
| `dist/<Курс>_<NN>_<Тема>_студенты.html` | самостоятельное изучение |
| `dist/moodle/<Course>_<NN>_<Topic>_pair_SCORM.zip` | пакет SCORM 1.2 для Moodle, версия для пары |
| `dist/moodle/<Course>_<NN>_<Topic>_students_SCORM.zip` | пакет SCORM 1.2 для Moodle с оценкой за итоговый тест |

Шрифты, иконки и фоны встроены в файл, внешних запросов нет. Второй дизайн (`tokens-mine.css`) собирается только по просьбе автора: `python3 build.py --variant`. Фрагменты для публикации артефактом: `--artifact`.

Сдаются четыре файла из таблицы. Если автор просит и интерактивную, и обычную презентацию, сдаются эти четыре файла и четыре файла основного режима (PPTX и PDF). Имена SCORM-пакетов пишутся латиницей: Moodle и Windows иногда портят кириллицу в именах архивов.

## 2. Порядок работы

1. Скопировать заготовку: `cp -R <skill>/assets/interactive <папка темы>/presentation`.
2. Источник, план и проверка плана: шаги 2-4 основного порядка работы из SKILL.md. `setup.py`, `content.js`, `make.py`, `lint_content.js` и `story.js` в этом режиме не нужны. Ориентир: версия для пары 60-80 слайдов, вся глава по разделам; студенческая версия - те же слайды плюс студенческие, обычно 100-130.
3. Заполнить `CONFIG` в начале `build.py`: код темы, префиксы имён, заголовки, папку рисунков главы.
4. Написать `src/slides.html` и `src/data.js` по образцу из заготовки. Образец содержит по одному слайду каждого вида; разметку брать оттуда, а не придумывать заново.
5. Стенды темы, если нужны, дописать в `src/stands.js` (объект `S`).
6. Собрать, открыть каждую версию в браузере на 1280×720 (через локальный сервер `python3 -m http.server` в папке `dist`) и выполнить содержимое `scripts/check_fit.js` в странице: вставить в консоль или передать инструменту выполнения JavaScript. Проверка провалена, если отчёт начинается со слов «НЕ ПОМЕЩАЕТСЯ» или называет внешние запросы. Чинить: сократить текст, разбить слайд, уменьшить схему; размер основного текста не уменьшать.
7. Рецензенты из `agents/README.md`: плановый, по фактам, студент-читатель, языковой редактор и проверка анимаций (`agents/animation-checker.md`). Находки проверки анимаций вносятся все, кроме противоречащих главе; после них проверка запускается ещё раз. Вместо `story.md` им дают пути к `src/slides.html` и `src/data.js`: оба файла читаются как текст. Слова-связки и длину текста `lint_content.js` здесь не ловит, их проверяет языковой редактор.
8. Посмотреть каждую живую схему на всех шагах на скриншотах. В скрытой панели браузера анимация может замереть: добавить стиль `.slide.active{animation:none}` в открытую страницу через JavaScript (не в исходники) и снять скриншот ещё раз.
9. Сдать четыре файла и написать короткий отчёт: число слайдов в каждой версии, какие рисунки стали схемами, что пропущено.

Полный пример темы, если он есть на машине автора: `cloud-computing/12_Containers_And_Cloud_Native/presentation/` в репозитории курсов. Пример собран на более ранней версии движка: у стрелок там нет класса `flow`.

## 3. Содержание пары и студенческой версии

Общие правила из `content-rules.md` действуют полностью:

- порядок «проблема → термин → механизм → пример → вопрос»;
- заголовок слайда - термин;
- определение на отдельной карточке в форме «**Термин** (term) - определение»;
- нет слов-связок «Поэтому», «Однако», «Начнём с»;
- только обычный дефис;
- лимиты текста.

Слайды и блоки одной версии помечаются `data-only="pair"` или `data-only="student"`. Всё без пометки попадает в обе.

**Пара.** Преподаватель рассказывает сам. На слайде структура и факты, текста мало. Вся глава идёт по порядку, по разделам.

**Студенты.** Презентация понятна без лектора. Поэтому в студенческой версии есть то, чего нет на паре:

- слайд «Как читать схемы» перед первым разделом;
- под каждой схемой одна строка: что слева, что справа, что меняется по шагам;
- вопросы для самопроверки и результаты обучения в начале;
- разбор типичных ошибок (`data-gen="mistakes"`);
- итоговый тест из 10 вопросов (`data-gen="final"`) и слайд с результатом;
- калькуляторы и упражнения;
- список источников.

Подпись под схемой пишется без воды: «По рисунку 8.2. Слева пользователи, в центре балансировщик, справа два сервера». Описывается, что изображено, а не пересказывается слайд.

## 4. Рисунки становятся живыми схемами

Это правило только для интерактивного режима. В PPTX рисунки остаются картинками.

- Каждый рисунок, на который ссылается текст главы, становится живой схемой из узлов, групп и стрелок. Схема собирается по шагам клавишей →.
- Схема не обязана буквально копировать рисунок, но передаёт ту же мысль. Она показывает то, что на статичной картинке не видно: запрос идёт по стрелке, тег переезжает на новый образ, упавший сервер заменяется новым.
- Один рисунок - одна схема. Схему не дублируют картинкой.
- Под схемой стоит подпись: на паре «По рисунку N», у студентов «По рисунку N. Что изображено».
- Под схемой идут подписи к шагам в блоке `.caps`: шаг 0 ставит вопрос, каждый следующий шаг объясняет одно изменение.
- Статичной картинкой (`{{fig:имя|номер|подпись}}`) остаётся только то, что не схема: скриншот консоли, график, фотография.

## 5. Иконки AWS для курса Cloud Computing

В облачном курсе узлы схем рисуются официальными иконками AWS Architecture Icons. Это иконки сервисов, ресурсов и групп из пакета AWS.

- Сначала иконку ищут в SVG-рисунках главы: рисунки курса нарисованы этими иконками. Фрагмент иконки вырезают в отдельный файл `src/icons/<имя>.svg`.
- Если в рисунках главы иконки нет, ищут её в официальном пакете Asset Package на странице `aws.amazon.com/architecture/icons`. Скачивание - это загрузка файла: перед ним спрашивают автора и называют файл и источник. Можно попросить автора скачать пакет самому.
- Иконку не перекрашивают и не искажают: так требуют правила AWS. Размер задаётся классом узла.
- Чёрные контурные иконки (пользователь, код, документ) вносятся в `CONFIG["line_icons"]`, чтобы в тёмной теме они инвертировались.
- В заготовке уже есть 23 иконки: ALB, CloudWatch, EC2, ECR, ECS, Fargate, Lambda, RDS, S3, Secrets Manager, контейнер, образ, задача, сервис, реестр и контурные.
- Если иконки нет ни в рисунках главы, ни в заготовке, а скачать пакет нельзя, узел временно рисуется без иконки, с подписью, и в отчёте называется, каких иконок не хватает.
- В других курсах (PHP, C++) узлы рисуются без иконок или простыми контурными SVG-иконками в стиле заготовки (вид 24×24, линия 1,5, чёрный цвет); такие иконки вносятся в `line_icons`.

## 6. Стрелки и анимация

Анимация - главное, чем интерактивная презентация лучше PPTX, и её не ограничивают. Чем больше механизма видно в движении, тем лучше. Анимируют появление узлов, перемещение тега, подсветка, замена упавшего сервера, каскад слоёв - всё, что помогает увидеть механизм. Точка на стрелке показывает, что от одного узла к другому что-то идёт, и её ставят почти на все стрелки схемы.

| Стрелка | Когда |
|---|---|
| `.link` | связь, по которой ничего не движется: статичная |
| `.link.on` (через `data-on="k"`) | шаг дошёл до этой связи: стрелка становится тёмной |
| `.link.flow` | по стрелке что-то идёт (код, образ, коммит, запрос, событие, журнал): пока стрелка включена, по ней бежит точка |
| `.link.r` | цвет «работает» вместо цвета «сборка» |
| `.link.v` | вертикальная стрелка |

Как устроена стрелка:

- Наконечник - ровный треугольник точно по центру линии.
- Точка - круг 10 px. Она плавно разгоняется и тормозит, перед наконечником гаснет.
- В цепочке из нескольких стрелок точки стартуют по очереди, волной. Движок ставит задержку сам.
- `data-on="1 3"` включает стрелку на шагах 1 и 2, с шага 3 она снова гаснет. Так останавливают поток к упавшему серверу.

Точка нужна, когда по стрелке идёт код, образ, коммит, запрос, событие или журнал: `docker build` (код уходит в сборку), `docker push` и `pull`, `docker run`, этапы конвейера CI/CD, выпуск и запуск, запросы пользователей. Без точки остаётся только стрелка, по которой ничего не движется: «содержит», «зависит от», «использует пароль из». Если сомневаешься, ставь точку.


## 7. Стенды и вопросы

**Стенд** - интерактивный элемент, в котором студент что-то нажимает и видит результат.

- Над стендом одна строка инструкции через `task("Нажмите…")`. Текста минимум, никаких абзацев объяснений внутри стенда.
- Стенд, который повторяет живую схему, не делается.
- Калькуляторы и упражнения на классификацию идут только в студенческую версию.
- Код с пояснением строк (`data-stand="code"`) и разбор команды (`data-stand="cmd"`) уместны в обеих версиях.
- QR-кодов нет: у студентов нет аккаунтов, через которые работало бы голосование.

**Вопросы.**

- Слайд `<section class="slide s-q" data-q="id">` строится из `DATA.q[id]`.
- Студент нажимает на вариант, и на том же слайде появляются верный ответ и объяснение. Клавиша → тоже показывает ответ.
- Вопросы на разминку берутся из прошлой главы, ключи `warm1`, `warm2`.
- Вопросы итогового теста - `f1`…`f10`. Верные ответы распределены по разным буквам.
- Вопрос самодостаточный: в нём нет имён классов, сценариев и переменных из примеров главы.

**Длинные списки** (двенадцать факторов, семь уровней) показываются по одному пункту на шаг через `data-gen="series"`. Пустой `<div class="list">` рядом заполняется оглавлением.

## 8. Дизайн

Бренд курса из `brand.md`:

- шрифт Manrope;
- цвета индиго `#4F46E5` и голубой `#0EA5E9`;
- белые слайды;
- градиент только на титуле и разделителях.

Титульный слайд повторяет `titleSlide` основного движка:

- плашка с названием курса;
- крупный заголовок;
- короткая полоса;
- «Nartea N.»;
- «Лекция N · Информатика и прикладная информатика».

Моноширинный шрифт Geist Mono используется только для кода, команд и терминала. JetBrains Mono не используется.

Без признаков шаблонного дизайна:

- без подписей капслоком моноширинным шрифтом;
- без эмодзи;
- без градиентного текста;
- без карточек внутри карточек.

## 9. Слабые компьютеры

Презентацию показывают на старых компьютерах в аудитории и открывают в Moodle на дешёвых ноутбуках и телефонах. Заготовка уже настроена под это. Правила ниже не дают сломать настройку.

**Как анимировать.** Количество и виды анимации не ограничены. Правила ниже не уменьшают анимацию: слабый компьютер обслуживает лёгкий режим, а в обычном режиме анимаций столько, сколько нужно. Чтобы анимация шла плавно:

- движение и появление делать через `transform` и `opacity`: их браузер считает на видеокарте;
- тени, фильтры, размытие и изменение размеров допустимы, но в лёгком режиме их нужно отключать правилом `.lite ...` в `deck.css`;
- не ставить `will-change` на множество элементов: браузер сам выносит анимацию в отдельный слой на время её работы.

**Когда работает анимация.**

- Неактивные слайды скрыты через `display:none`, поэтому их анимации не работают.
- Стенд монтируется при первом показе слайда, а не при загрузке страницы.
- Таймеры стендов (`setInterval`) запускаются только на активном слайде: `onActive(el, start, stop)` из `stands.js`.
- Нет циклов `requestAnimationFrame` в простое. Если вкладка скрыта, анимации ставятся на паузу (класс `paused`).

**Лёгкий режим** (класс `lite` на `<html>`).

- Включается сам, если у компьютера не больше двух ядер или не больше 2 ГБ памяти, если в системе включено уменьшение движения или если в первые секунды получается меньше 30 кадров в секунду.
- Переключается клавишей L.
- В лёгком режиме нет бесконечных анимаций, перехода между слайдами и теней. Точка стоит в середине стрелки, шаги появляются сразу.

**Размер файла.**

- HTML не больше 1,5 МБ, сборщик предупреждает о превышении.
- Иконка встраивается один раз в CSS (`.ic-имя`), а не копией в каждый узел.
- SVG передаётся без base64 и без метаданных.
- Шрифты - только поднаборы latin и cyrillic в woff2 и только используемые начертания.
- Фоновые JPEG не больше 50 КБ.

**Совместимость.** Презентация работает в Chrome и Edge 109: это последняя версия для Windows 7 и 8.1, такие компьютеры ещё стоят в аудиториях. Также она работает в Firefox ESR 115. Поэтому:

- нет `color-mix()`: прозрачные оттенки задаются готовыми токенами `--build-line`, `--run-halo` и подобными; новый токен добавляется в оба файла `tokens-brand.css` и `tokens-mine.css`, во втором также в оба тёмных блока;
- нет вложенного CSS (nesting);
- нет `@container`;
- нет единиц `dvh` и `svh`;
- `:has()` не используется для раскладки;
- `text-wrap: balance` допустим только как украшение, без которого слайд тоже читается.

**Раскладка.**

- Сцена 1280×720 масштабируется одним `transform: scale`.
- Шаг переключает классы, а не перестраивает DOM.
- Тексты не измеряются в JavaScript.

**Проверка.**

- В Chrome DevTools открыть Performance, включить CPU throttling 6× и пролистать слайды со схемами: переходы и точки не должны дёргаться.
- Нажать L и пролистать ещё раз.

## 10. Навигация и Moodle

**Навигация.**

- Всегда режим презентации 16:9: сцена масштабируется под окно, в том числе под окно Moodle. Режима ленты с прокруткой нет; правила `.reflow` в `deck.css` остались от ранней версии и не используются.
- Бренд - одна светлая тема для проектора. Кнопка «Тема» и тёмная тема есть только во втором дизайне, в бренде кнопка убирается сама.
- Внизу панель: «Все слайды», «← Назад», «N из M», «Далее →», «Во весь экран».
- Клавиши:
  - → и PageDown: следующий шаг, затем следующий слайд;
  - ←: назад;
  - O: список слайдов;
  - F: полный экран;
  - L: лёгкий режим.
- Работают кликер и свайп.
- На телефоне в портретной ориентации появляется подсказка повернуть экран.

**SCORM 1.2.** Это уже есть в `deck.js`:

- статус `incomplete` при входе;
- `lesson_location` для возврата на последний слайд;
- оценка `score.raw` за итоговый тест студентов;
- статус `completed`: на паре после последнего слайда, у студентов после ответа на все вопросы теста.

Проходной балл задаётся в `CONFIG["mastery"]`, по умолчанию 60.

**Загрузка в Moodle.** «Добавить элемент» → «Пакет SCORM» → загрузить zip. В настройках «Отображать пакет» выбрать «В текущем окне», ширина 100%, высота около 720.

## 11. Разметка: справочник

**Шаги.**

| Атрибут | Действие |
|---|---|
| `data-in="k"` | элемент появляется на шаге k |
| `data-out="k"` | элемент исчезает на шаге k |
| `data-on="k"` или `data-on="k m"` | класс `on` с шага k, до шага m |
| `data-cur="k"` | класс `cur` только на шаге k |

**Слайды.**

| Класс | Назначение |
|---|---|
| `.s-title` | титульный |
| `.s-div` | разделитель раздела, с `data-name` |
| `.s-q` | вопрос |
| `.result` | результат итогового теста |

**Блоки.**

| Класс | Назначение |
|---|---|
| `.grow` | содержимое по центру |
| `.cards.c2`, `.c3`, `.c4` | карточки |
| `.card.def` | определение |
| `.card.b`, `.card.r` | цвета «сборка» и «работает» |
| `.after` | строка после блока |
| `.two` | две колонки |
| `.stand` | стенд |
| `.series` | список по шагам |

**Схема.**

| Класс | Назначение |
|---|---|

## 12. Проверки перед сдачей

- `scripts/check_fit.js` в открытой странице на 1280×720 сообщает, что все слайды помещаются на всех шагах и внешних запросов нет. Проверяются обе версии.
- Скриншоты каждой живой схемы на каждом шаге:
  - стрелки соединяют нужные узлы;
  - подпись шага совпадает с тем, что изменилось;
  - точки бегут только по стрелкам `flow`.
- Проверка анимаций (`agents/animation-checker.md`) не нашла схем без движения, стрелок с передачей без точки и слайдов-процессов без анимации.
- Лёгкий режим (клавиша L): схемы читаются, ничего не пропало.
- Рецензенты:
  - плановый;
  - по фактам;
  - студент-читатель, только по студенческой версии;
  - языковой редактор с блоком «Language focus».
- SCORM на тестовом API. Перед загрузкой страницы задать `window.API` с методами `LMSInitialize`, `LMSSetValue`, `LMSGetValue`, `LMSCommit` и `LMSFinish`, которые записывают вызовы, и проверить:
  - вход;
  - возврат на последний слайд;
  - оценку 70 за 7 верных ответов из 10;
  - статус `completed`.
