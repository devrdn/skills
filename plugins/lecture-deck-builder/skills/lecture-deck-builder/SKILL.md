# Сборка презентаций к лекциям

Скилл превращает одну главу университетского курса в презентацию на лекцию 70-80 минут в фирменном стиле автора. Предмет может быть любым (облачные вычисления, PHP, C++, новый курс): всё содержание берётся только из источника, который дал пользователь.

Автор - преподаватель университета, пишет по-русски. Слайды, заголовки, отчёт и сообщения автору - на языке пользователя, обычно на русском.

## Два режима

| | Обычный | Динамический |
|---|---|---|
| Как просят | «презентация», «слайды», «версия для пары» | «динамическая», «интерактивная», «HTML», «с анимациями», «SCORM», «для Moodle» |
| Результат | версия преподавателя и студенческая, каждая в PPTX и PDF; по просьбе короткая версия для пары | HTML для лекции («пара»), она же с командным квизом («пара_квиз»), студенческая версия, два пакета SCORM |
| Рисунки главы | картинки | живые схемы, которые собираются по шагам |
| Источник слайдов | `content.js` для движка pptxgenjs | `src/slides.html` и `src/data.js` в копии `assets/interactive/` |
| Порядок сборки | `references/regular/workflow.md` | `references/dynamic/workflow.md` |

Режим выбирается по словам запроса. Если просят просто презентацию, режим обычный; в первом сообщении назови выбранный режим, чтобы автор успел его сменить, пока работа не ушла далеко. При правке готовой презентации режим сохраняется: папка с `src/slides.html` - динамический, папка с `content.js` - обычный. Если автор просит оба режима, план общий, а сдаются обе сборки.

## Что нужно для работы

`<skill>` в командах - папка этого скилла (где лежит SKILL.md).

- **Обычный режим:** node и npm, python3, LibreOffice (`soffice`) для PDF, `pdftoppm` (poppler) для картинок страниц. `scripts/setup.py` ставит npm- и pip-пакеты и шрифты, а об отсутствии node, soffice и pdftoppm только сообщает: их установку предложи автору.
- **Динамический режим:** python3 (сборка), node (`scripts/story_html.py` читает `data.js`), браузер с выполнением JavaScript и скриншотами (встроенный браузер или Claude in Chrome) для `check_fit.js` и просмотра схем.
- **Без браузера** собери презентацию и выгрузи story.md, запусти рецензентов, а в отчёте прямо скажи, что `check_fit.js` и скриншоты схем не выполнены и что их нужно сделать перед лекцией.
- **Без инструмента Agent** рецензии делаются по запасному порядку из `agents/README.md`.

## Порядок работы

Если в среде есть список задач, веди его: работа долгая, и автор следит за ходом по нему. Проверку плана сделай отдельной задачей, а проверку результата - последней.

Порядок постоянный: **источник → план по слайдам → проверка плана → сборка → рецензенты → сдача**. Ни один слайд не пишется, пока план не проверен и не исправлен. Передвинуть строку плана ничего не стоит; передвинуть готовые слайды - значит переписать их вводные строки, а в динамическом режиме ещё и схемы с шагами.

### 1. Источник

Получи полный текст главы и всё, на что она опирается.

- **GitHub.** Получи структуру репозитория, не скачивая файлы:
  ```bash
  git clone -q --depth 1 --filter=blob:none --no-checkout https://github.com/<owner>/<repo> src_repo
  git -C src_repo ls-tree --name-only HEAD              # папки глав
  git -C src_repo ls-tree -r --name-only HEAD <folder>  # файлы одной главы
  ```
  Файлы читай через `git -C src_repo show HEAD:<path> > chapter.md` или `curl -sL https://raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>`. `gh api` и WebFetch на страницах github.com в некоторых средах заблокированы.
- **Веб-страница:** WebFetch. **Локальный файл или загрузка:** прочитай его.
- **Глава названа только номером или темой** («глава 12 по PHP»): поищи её в рабочей папке и в репозитории курса рядом (папки вида `12_Templating/readme.md`); если не нашёл или нашёл несколько, спроси у автора путь или ссылку.
- **Рисунки**, на которые ссылается глава: запиши их номера и файлы; как их использовать, сказано в файле порядка работы своего режима.
- **Прошлая глава** - для 1-2 вопросов на разминку (как её найти: `references/common/questions.md`). Если найти её не удаётся, попроси у пользователя ссылку.

Сохрани главу и прошлую главу в рабочую папку отдельными файлами: их читают рецензенты. Рабочая папка в обычном режиме - папка, которую готовит `scripts/setup.py`; в динамическом - папка `presentation/` рядом с главой (её создаёт первый шаг сборки, а `chapter.md` и `plan.md` можно положить туда сразу). Если папка `presentation/` у главы уже есть, это правка готовой презентации: не копируй заготовку поверх, а работай по разделу «Правки после замечаний» или спроси автора, начинать ли заново. Прочитай главу целиком. Выпиши понятия, механизмы, примеры и код, рисунки, сноски, вопросы для самопроверки, практические задания, а отдельно - ошибки и противоречия источника для итогового отчёта.

### 2. План по слайдам

Напиши в рабочей папке `plan.md`: разделы лекции и в каждом разделе по строке на слайд.

```
[N] заголовок · вид · одна мысль слайда · needs: термины, функции, программы, рисунки, на которые он опирается
```

`вид` - форма слайда: определение, карточки, сравнение, шаги, код, рисунок, вопрос, итоги. В динамическом режиме строка ещё и указывает, что движется, чтобы рецензент оценил анимацию до сборки:

```
· motion: <что движется, какая механика, сколько шагов>      или      · static
```

Фрагмент плана динамической лекции:

```
## 4. Метод 2: шаблоны с метками
[30] Метка и шаблон с метками · определение · шаблон - HTML без PHP, на месте данных метки · needs: - · static
[31] Реализация метода 2 · карточки · идея метода; файлы и функции примера главы · needs: метка · static
[32] Функция strtr() · карточка функции · заменяет подстроки по массиву замен, возвращает строку · needs: - · static
[33] Устройство fillTemplate() · живая схема (рис. 12.3) · значения встают на места меток · needs: strtr(), метка · motion: значения из массива по одному переезжают в метки шаблона (slot + chip), 3 шага
[34] Что выведет strtr() · вопрос · подстановка одной метки дважды · needs: strtr() · static
```

Прежде чем отдать план рецензенту, проверь его сам:

1. **Бюджет.** Обычный режим: 70-90 содержательных слайдов, жёсткий максимум 100 (`references/common/content-rules.md`, §3). Динамический режим: версия для пары 60-80 слайдов, вся глава по разделам; в студенческой версии есть ещё свои слайды, всего обычно 100-130. В лекцию идёт только ядро главы; каждый слайд отвечает на вопрос «что студент должен здесь понять».
2. **Порядок.** Всё из «needs» появляется в более ранней строке; каждый раздел идёт в порядке понимания (проблема, термин, механизм, пример, вопрос на проверку, ограничения); ни одну тему не бросают на полпути, чтобы вернуться к ней позже (`references/common/content-rules.md`, §5).
3. **Проверка связности.** Прочитай подряд одни заголовки: они должны складываться в связный план, и каждый должен говорить, о чём его слайд. Заголовок «Две задачи страницы» ничего не говорит, пока не увидишь слайд; «Обработка и вывод в одном файле» - говорит.
4. **Проблема, определение, решение:** так вводится каждое новое понятие; каждый новый термин получает свою карточку определения (`references/common/content-rules.md`, §7).
5. **Только динамический режим:**
   - для каждой функции, которую использует слайд с кодом или схема, раньше идёт карточка функции (вызов, что делает, что возвращает), в том числе для встроенных функций;
   - перед кодом метода или подхода, который глава реализует своими функциями, стоит слайд «Реализация метода N», и он говорит, что это один из способов реализации;
   - каждый рисунок главы - живая схема; каждый процесс главы показан в движении, и строка motion называет, что именно движется; определения, факты, плюсы и минусы, синтаксис и итоги статичны;
   - если ни одна механика заготовки не показывает процесс хорошо, план предлагает новую («new mechanic: ...»). Анимацию не нормируют: у слайда столько движения, сколько у его процесса этапов.

Если ядро главы не помещается в бюджет, **остановись и скажи пользователю**: сколько слайдов нужно, что пришлось бы убрать, и варианты (сократить названные разделы, разбить на две лекции с указанной границей, поднять лимит). Если пользователь разрешил решать самому или спросить некого, сокращай по правилам отбора и перечисли сокращения в отчёте.

### 3. Проверка плана агентом

Запусти рецензента плана (`agents/plan-reviewer.md`; как запускать, описано в `agents/README.md`) на plan.md и укажи в задании режим. Рецензент видит только план, как студент, который не читал главу, поэтому замечает пропуски, которые автор плана незаметно для себя заполняет в голове.

Внеси замечания в plan.md. Если при этом передвинуто, добавлено или убрано больше десятка строк, запусти рецензента ещё раз на новый план. Потом сразу переходи к сборке: автору нужна готовая презентация, поэтому одобрения плана не жди. Останавливайся и показывай план, только если автор сам попросил сначала план или если не сходится бюджет (шаг 2).

### 4. Сборка

Пройди файл порядка работы своего режима с первого шага:

- обычный: `references/regular/workflow.md` - подготовка, content.js, lint, этап B, сборка, этапы C и D, студенческая версия, сдача; версия для пары - `references/regular/pair-deck.md`;
- динамический: `references/dynamic/workflow.md`, раздел «Порядок работы» - скопировать заготовку, написать слайды и данные по плану, собрать три версии, проверить каждый шаг в браузере, запустить рецензентов и проверку анимаций, посмотреть каждую схему на каждом шаге.

Рецензенты и этапы описаны в `agents/README.md`: рецензент по фактам, проверка кода, студент-читатель и языковой редактор работают в обоих режимах, проверка вёрстки - в обычном, проверка анимаций - в динамическом. Языковой редактор всегда получает блок «Языковой фокус» ниже.

### 5. Отчёт

Коротко, на языке пользователя:

- число слайдов в каждой версии, примерное время;
- что сокращено из источника, если сокращено, и изменился ли порядок разделов главы;
- ошибки и неточности источника (списком, с местом в главе);
- 3-5 слайдов, которые можно пропустить, если не хватит времени;
- какие рецензенты работали и сколько было кругов (включая проверку плана) или что проверки выполнены без отдельных агентов;
- динамический режим: какие рисунки стали живыми схемами и какие механики добавлены;
- если лекция упёрлась в лимит или материала мало, скажи об этом и предложи вариант.

Не пересказывай шаги работы.

### Языковой фокус

Добавляй этот блок к заданию языкового редактора в любом режиме и на любом этапе:

```
Дополнительный фокус: текст должен звучать как живая речь грамотного преподавателя, складно и естественно.
Прочитай каждый блок вслух про себя. Отмечай всё, что носитель русского языка сказал бы иначе:
- согласование рода, числа и падежа, особенно между заголовком карточки и её текстом, и в списках однородных членов;
- неверные предлоги и управление («влияет на», «зависит от», «отвечает за»);
- неестественный порядок слов, кальки с английского («делает репликацию», «имеет место», «в случае если»);
- телеграфный стиль: цепочки существительных без глагола там, где нужна фраза;
- разные грамматические формы в параллельных блоках одного слайда (все с глагола или все с существительного);
- тяжёлые конструкции с несколькими родительными подряд («изменение параметров настройки репликации базы»);
- одно и то же слово в соседних блоках.
Предлагай вариант не длиннее исходного, сохраняй термины и факты.
```

## Правки после замечаний

Автор обычно присылает точечные замечания («убери этот слайд», «переименуй», «сначала проблема, потом решение», «стрелка не попадает в рамку»). Сохрани прошлую версию (`content.v1.js`, `slides.v1.html`), поправь исходник слайдов, пересобери все версии, прогони все проверки и снова отправь файлы. После правки проверь изменённые слайды на порядок и лимиты текста; если замечание касается порядка, связей или формулировок по всей презентации, снова запусти студента-читателя или языкового редактора. Замечание, которое добавляет или переставляет несколько слайдов, сначала проходит через plan.md и рецензента плана.

Общее замечание (например, «заголовки должны быть терминами», «скажи, что делает функция, прежде чем её анимировать») распространяй на всю презентацию, а не только на слайд, где оно прозвучало. Не меняй то, что автор уже одобрил и не упоминал (формулировки заголовков, подпись курса, принятую структуру), если это не нарушает правило; если правило и одобренный выбор противоречат друг другу, оставь одобренный выбор и скажи об этом.

Если замечание становится новым постоянным правилом для всех лекций, ему место в этом скилле: скажи автору, что его можно добавить.

**Что читать при правке.** План и общие правила целиком не нужны. Прочитай только то, что касается замечания: в обычном режиме - нужный тип слайда в `references/regular/slide-api.md` и команды сборки в `references/regular/workflow.md`; в динамическом - `references/dynamic/markup.md`, а для схем и анимации `references/dynamic/animation.md`. Если в новой сессии в рабочей папке нет `node_modules` или движка, снова запусти `scripts/setup.py`: он безопасен при повторном запуске.

**Как найти «слайд N».** Автор называет номер страницы PDF или номер на панели HTML.
- Обычный режим: номер в `WARN [слайд N]` и в PDF совпадает, а индекс в content.js - нет: `predict` и `tablebuild` занимают по две страницы, а в студенческой версии нет квиза. Найди слайд по заголовку на этой странице PDF (`pdftotext -f N -l N`) и проверь, какой версии принадлежит номер.
- Динамический режим: номер на панели - порядковый номер слайда в собранной версии; найди его по заголовку в `story.md` из `scripts/story_html.py` (номера [N] там те же) и затем в `src/slides.html`.

**Обязательные проверки после правки.** Обычный режим: `lint_content.js` без ERROR, сборка без WARN, `check_all.py` и `footer_scan.py` без замечаний, просмотр изменённых страниц. Динамический: сборка, `check_fit.js` на всех версиях, скриншоты изменённых слайдов на всех шагах. Рецензенты - по правилу выше.

**Версия для пары.** `content_pair.js` находит слайды основной презентации по заголовку (`pick(type, title)`): если правка переименовала слайд, поправь и вызов `pick`, иначе версия для пары молча потеряет слайд.

## Варианты по просьбе

- **Двуязычный квиз** (английский под русским), обычный режим: `questionEn`, `optionsEn`, `answerEn` (`references/regular/slide-api.md`, §5).
- **Без квиза:** убери раздел квиза и его пункт плана; в динамическом режиме не собирай файл «пара_квиз».
- **Другая длина:** пересчитай бюджет из расчёта 0,8-1 минута на содержательный слайд.
- **Второй дизайн** динамической презентации: `python3 build.py --variant`.
