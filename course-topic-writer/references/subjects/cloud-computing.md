# Cloud Computing

- _Keywords_: облачные вычисления, Cloud Computing, облако, cloud, AWS.
- _Audience_: USM, 3rd year, programmes Informatică and Informatică aplicată (lab requirements differ between them). Mixed level; aim at the average student: not a school intro, not DevOps experience either.
- _Prerequisites_: programming basics, algorithms and data structures, computer networks basics (IP, TCP, UDP, HTTP, HTTPS, DNS as a concept, ports), operating systems basics (process, file system, basic Linux terminal), C++, Node.js, PHP, web development. Network concepts a chapter builds on still get a short reminder.
- _Language and platform_: Russian. AWS is the main platform and the default source of service examples. Google Cloud only where the comparison shows a concept is wider than one vendor (EC2 and Compute Engine, S3 and Cloud Storage, RDS and Cloud SQL, Lambda and Cloud Run functions, EKS and GKE). The course is not an AWS catalogue: the subject is cloud computing principles, AWS is the playground.
- _Repository and files_: `MSU-Courses/cloud-computing`, each chapter in `NN_Name/readme.md`, images in `_images/NN/`, labs in `Lab/`. Last year's course `MSU-Courses/cloud-computing-old` is reference only: structure and ideas may be reused, claims must be verified, text is never copied. If the user says not to use it, don't.
- _Course plan_: 15 chapters in five parts (foundations, building blocks, distributed applications, security and operations, architecture). Written so far: 01 Введение в облачные вычисления; 02 Архитектура облачных систем и основы виртуализации (names block, file and object storage briefly); 03 AWS и глобальная архитектура (regions, AZs, account, budgets, tags, IAM users, groups, roles, policies, console, CLI, SDK); 04 Вычислительные сервисы и идентификация машин, Amazon EC2 (EBS and instance store introduced); 05 Облачные сети, Amazon VPC; 06 Облачные хранилища, Amazon S3, EBS и EFS (models of storage, S3 in depth with classes, prices, versioning, encryption, policies, presigned URLs; EBS; EFS; data protection with RPO and RTO; hands-on 6.1-6.3). The author's version of chapter 6 in the repository is the reference for structure and style. Terraform, Kubernetes, Docker and CI/CD are not covered in depth (separate courses). Reliability topics (RTO, RPO, SLA, SLO, blast radius, DR) are spread across chapters and tied to concrete services. The six AWS Well-Architected pillars run through the course and are covered in depth in the last chapter. Check the repository for the current chapter list.
- _Running project and story_: each chapter opens with a story in `<i>...</i>` about the students Эмма and Джон. The author writes the story: never write one unasked and never touch its text during style edits. When asked to write one, continue the previous chapter's story (the problem it ended on is solved, a new one leads into this chapter's topic), use plain language, end on the question the chapter answers, and format dialogue like the previous chapter (`– "Реплика, - сказал он. - Продолжение".`). Story dialogue lines start with a dash; that is the author's choice and the dash rule does not apply there. Эмма and Джон never appear in the main text. The course application grows from lab to lab (TimeCapsule in labs 2-4).
- _No labs in chapters_: chapter text, the story and the retrospective never mention lab works or the course application. Hands-on links are fine, and a teaching scenario may happen to be about labs ("сервис сдачи лабораторных работ").
- _Special elements_:
  - When a service is covered for the first time, the topic has a service card: table `| Характеристика | Amazon X |` with rows Категория, Что делает, Для чего нужен, Где используют, Модель обслуживания, Область действия, Как оплачивается, Как работать, Появился, Аналоги. The service model follows the responsibility boundary from chapter 1: a raw resource you administer yourself is IaaS (EC2, EBS, VPC), a managed service where AWS runs the servers and software and you manage only data and access is PaaS (S3, EFS).
  - AWS prices come from the official pricing pages for `eu-central-1` unless the chapter says otherwise. The pages are rendered from JSON at `https://b0.p.awsstatic.com/pricing/2.0/meteredUnitMaps/<service>/USD/current/<service>.json` (data transfer: `datatransfer`); if the shell cannot reach it, open the pricing page in a browser and fetch that JSON from the page.
  - A service section follows one order: why it is needed; what it is (definition and service card); "Основные характеристики Amazon X" (a paragraph with the main idea, a table "Важные параметры X" with the numbers that tell services apart: copies, replicas, AZs, size limits, retention, and a paragraph "Не путайте..."); mechanisms; cost; comparison with neighbours. A chapter with several services ends with a table comparing copies, replicas and AZs.
  - Consequences for the application are cloud-specific: a failover drops connections, responses come in pages, a restore creates a new endpoint, an address may change.
  - From chapter 4 on, step-by-step console work lives in separate hands-on files (`hands_on_NN.md`); the topic keeps a short note that it is in the hands-on.
  - Architecture diagrams in AWS style with the official AWS Architecture Icons, showing only components students have already studied.
- _No links to other chapters_: the text never links to another chapter. An earlier chapter is named only in the retrospective or where a fact really comes from it, never in place of an explanation.
- _AWS feature names_: as in the console and documentation (Global Tables, DynamoDB Streams, Multi-AZ DB instance deployment), not a Russian calque as the main name.
- _Overrides_: straight quotes `"..."`. The `#` title has no chapter number. Figure captions in this course are `_6.1. Название_` (chapter and number without the word "Рисунок"), referenced in text as "на рисунке 6.1". Run the checker with `--plain-captions`.
